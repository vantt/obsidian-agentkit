## Reading
- **No silent failure.** The CLI prints "unable to find Obsidian" with exit 1, and the bridge maps it to exit 2 (README case 2). Nothing came back empty with exit 0.
- F1 for this setup (different account, elevated): **fails loudly, bridge handles it**. No fix needed for silent failure.
- Minor: the bridge said "Obsidian is not running", but Obsidian was running under another account. **Fixed** in `obs.mjs`: the reason now reads "Obsidian is not running, or runs as another user (admin shell?)", and the `--preflight` NEXT line says to use a terminal under the same Windows user, not "Run as administrator". Tests: same 24 pass / 7 fail before and after the change (the 7 failures already existed; run from the Admin account).
- Minor: when `obsidian` is not on PATH, the bridge reports `cli=none (Obsidian CLI not found)`, which is correct.

## Same-account elevation
- `net localgroup administrators` lists only the admin accounts. `<user>` is a standard user, so "Run as administrator" from that account asks for the admin account's password and opens the shell as the admin account. That is the setup tested above, so on this machine the run above is the real-world admin-terminal case.
- Same account with UAC elevation (a user who is also an administrator) cannot be tested on this machine. It is left open for a machine where the Obsidian user is an administrator.
