# E3.3b: một tuần chỉ đọc trên vault thật (bảng ghi)

Mục tiêu: dùng agent hỏi vault thật trong một tuần, **chỉ đọc**: tìm kiếm, backlink, đếm task. Không có câu trả lời sai nào được lọt qua; ghi lại mọi chỗ skill `obsidian-connect` thiếu hoặc sai. Bảng này là đầu vào cho E3.5b và E3.6b.

## 1. Bắt đầu

1. Mở Obsidian, mở đúng vault cần dùng.
2. Bắt đầu phiên agent bằng câu này (dán nguyên văn, thay tên vault):

   > Dùng skill obsidian-connect. Vault của tôi tên là "<tên vault>". Chạy `--preflight --vault "<tên vault>"` trước. **Tuần này chỉ đọc**: tuyệt đối không ghi, không tạo, không sửa, không đổi tên, không di chuyển, không xóa, không chạy `--prop-set`, `--append`, `--create`, `--daily-append-once`, `--tag-rename`, `--rename`, `--move`, `--trash`. Nếu một câu hỏi cần ghi, hãy dừng và nói cho tôi biết thay vì làm. Với mỗi câu trả lời, nói rõ bạn dùng lệnh nào; nếu kết quả có chữ `APPROXIMATE:` thì nhắc lại trong câu trả lời.

3. Kiểm tra lúc đầu và lúc cuối tuần: nếu vault là git repo, `git status` phải sạch như trước (agent không được để lại thay đổi nào); nếu vault ở Google Drive, không có file mới dạng `... (1).md`.

## 2. Bảng ghi (một dòng cho mỗi câu hỏi)

Cột "Đúng?" chỉ dùng ba giá trị: **đúng**, **sai** (câu trả lời mâu thuẫn với vault), **thiếu** (trả lời đúng một phần, bỏ sót mục hoặc không trả lời được). Kiểm tra bằng cách đối chiếu với cách làm trên file ở mục 4.

| Ngày | Câu hỏi đã hỏi | Câu trả lời của agent | Đúng? (đúng/sai/thiếu) | Thiếu gì / sai gì | Skill hoặc lệnh bridge đã dùng |
|---|---|---|---|---|---|
| YYYY-MM-DD | | | | | |
| | | | | | |
| | | | | | |
| | | | | | |
| | | | | | |

Thêm dòng khi cần. Với mỗi dòng **sai** hoặc **thiếu**, ghi thêm bên dưới bảng: lệnh agent đã chạy, kết quả thô của lệnh (cắt ngắn, che tên riêng tư), kết quả đúng theo cách kiểm tra trên file.

## 3. Mười câu hỏi mẫu (chỉ đọc)

Thay phần trong `<...>` bằng thứ có thật trong vault của bạn. Cột "Lệnh bridge" là lệnh agent nên dùng; nếu agent dùng cách khác (ví dụ grep trực tiếp khi Obsidian đang mở), ghi vào cột cuối của bảng.

| # | Loại | Câu hỏi mẫu | Lệnh bridge |
|---|---|---|---|
| 1 | Tìm kiếm | "Tìm các ghi chú nhắc đến `<từ khóa>` và cho tôi biết có bao nhiêu." | `obs --find "<từ khóa>"` |
| 2 | Backlink | "Những ghi chú nào liên kết tới `<đường dẫn ghi chú>`?" | `obs --backlinks path=<ghi chú.md>` |
| 3 | Đếm task | "Tôi còn bao nhiêu task chưa xong trong cả vault?" | `obs --tasks-count` |
| 4 | Tag | "Tag `#<tag>` xuất hiện bao nhiêu lần?" | `obs tag name=<tag> total` (danh sách tag: `obs tags counts sort=count format=json`) |
| 5 | Thuộc tính | "Ghi chú `<ghi chú.md>` có những thuộc tính (frontmatter) nào, giá trị gì?" | `obs properties path=<ghi chú.md> format=json` |
| 6 | Dàn ý | "Cho tôi dàn ý (các heading) của `<ghi chú.md>`, kèm số dòng." | `obs outline path=<ghi chú.md> format=json` |
| 7 | Liên kết hỏng | "Có bao nhiêu liên kết chưa trỏ tới ghi chú nào? Liệt kê vài cái." | `obs unresolved total`, `obs unresolved` |
| 8 | Daily note | "Daily note hôm nay viết gì?" (hoặc "Đọc `<ghi chú.md>`") | `obs daily:read` (không tạo note nếu chưa có); `obs read path=<ghi chú.md>` |
| 9 | Note mồ côi | "Có bao nhiêu ghi chú không có liên kết đến? Cho tôi xem 5 cái." | `obs orphans total`, `obs orphans \| head -5` |
| 10 | File gần đây | "Tôi mở những file nào gần đây nhất?" | `obs recents` |

Lưu ý khi đọc câu trả lời:

- `--find` khớp **cả từ**, không khớp một phần từ ("abandon" không khớp "abandoned"). Nếu bạn cần khớp một phần, ghi nhận là "thiếu" và ghi lại.
- `recents` là các file **đã mở gần đây trong ứng dụng**, không phải file **sửa gần đây**. Câu hỏi "file nào mới sửa" không trả lời được bằng `recents`.
- `orphans` đếm cả file đính kèm (ảnh, pdf), không chỉ ghi chú, và tính liên kết từ file `.canvas`; còn `--backlinks` không đếm `.canvas` và liên kết bằng tên bí danh (alias). Một note hiện 0 backlink vẫn có thể không phải note mồ côi.
- `unresolved` cũng liệt kê liên kết markdown và URL lạ, không chỉ `[[wikilink]]`.
- Đếm task: `--tasks-count` đếm `- [ ]` và cả `1. [ ]`; task trạng thái `[/]` hoặc `[-]` không tính là chưa xong.

## 4. Cách kiểm tra bằng file (chạy trong thư mục vault, không cần Obsidian)

Mở terminal tại thư mục vault: `cd "<thư mục vault>"`. Các lệnh này chỉ đọc. Kết quả có thể lệch nhẹ so với Obsidian ở mục "Lệch hợp lý"; lệch lớn hơn thì ghi vào bảng.

| # | Cách tính đáp án trên file | Lệch hợp lý |
|---|---|---|
| 1 | Số ghi chú: `grep -rliwF --include='*.md' -- "<từ khóa>" . \| wc -l`; thêm ghi chú mà tên file có từ đó: `find . -iname '*<từ khóa>*.md'` | Obsidian bỏ qua file trong thư mục ẩn (bắt đầu bằng `.`); `grep -w` coi dấu `_` là một phần của từ, Obsidian thì không |
| 2 | `grep -rliE --include='*.md' '\[\[<tên ghi chú, không có .md>(\||#|\]\])' .` (liên kết wikilink; đường dẫn đầy đủ cũng được) | Không thấy liên kết kiểu `[chữ](ghi chú.md)` và liên kết nằm trong khối code (Obsidian bỏ qua khối code, grep thì không) |
| 3 | `grep -rhE --include='*.md' '^\s*([-*+]\|[0-9]+[.)])\s+\[ \]' . \| wc -l` | grep đếm cả dòng `- [ ]` nằm trong khối code; Obsidian không đếm |
| 4 | `grep -rhoiE --include='*.md' '(^\|[[:space:]])#<tag>([^[:alnum:]/_-]\|$)' . \| wc -l`, cộng thêm các `tags:` trong frontmatter | Tag không phân biệt hoa thường; tag lồng (`#a/b`) không tính vào `#a` ở cách đếm này |
| 5 | `sed -n '1,/^---$/p' "<ghi chú.md>"` (hoặc `head -30`) rồi đọc khối giữa hai dòng `---` | Số, true/false, ngày hiện dạng văn bản trong file nhưng Obsidian trả về kiểu số/bool |
| 6 | `grep -nE '^ {0,3}#{1,6} ' "<ghi chú.md>"` (số dòng bắt đầu từ 1) | Dòng `#` trong khối code bị grep đếm nhầm |
| 7 | Lấy một mục bất kỳ trong `obs unresolved`, rồi `find . -iname '<tên>*'` phải không ra gì; `grep -rF "[[<tên>" --include='*.md' .` phải có ít nhất một ghi chú | Tổng của Obsidian gồm cả liên kết markdown/URL, nên lớn hơn số wikilink hỏng đếm tay |
| 8 | `cat "<thư mục daily>/<YYYY-MM-DD>.md"`; nếu file không có, agent phải nói "chưa có" và không được tạo | `obs daily:path` cho biết đường dẫn theo cài đặt Daily notes |
| 9 | Một ghi chú cụ thể: `grep -rlF "[[<tên ghi chú>" --include='*.md' .` không ra file nào khác ngoài chính nó và tên không xuất hiện trong liên kết markdown thì là mồ côi. Tổng số: dùng script `tests/e33-readonly-check.mjs` trên vault thử, không có cách grep gọn | Ghi chú có `[[#Heading]]` trỏ vào chính nó thì không mồ côi; liên kết từ `.canvas` cũng tính |
| 10 | `grep -A12 '"lastOpenFiles"' .obsidian/workspace.json` | `workspace.json` ghi chậm vài giây sau khi mở file |

## 5. Báo lại gì (cuối tuần hoặc ngay khi gặp lỗi)

1. Bảng ở mục 2 đã điền (tối thiểu 10 dòng, mỗi loại câu hỏi ở mục 3 một dòng, thêm các câu thật bạn đã hỏi).
2. Với mỗi dòng sai/thiếu: lệnh đã chạy, kết quả thô (che tên riêng tư), đáp án đúng theo mục 4.
3. Có agent nào ghi vào vault không (`git status` hoặc file mới)? Nếu có, dừng tuần thử và báo ngay.
4. Obsidian có hiện hộp thoại bất ngờ không? Lệnh nào có `NEXT:` hoặc `STOP:` mà agent không làm theo?
5. Lệnh chậm hơn bình thường (đo thô, đơn vị giây) và lúc vault vừa mở.

Tiêu chí đạt E3.3b: không còn dòng "sai" chưa được giải thích; các dòng "thiếu" đã được ghi chú vào `skills/obsidian-connect/references/` hoặc backlog trước khi mở quyền ghi (E3.5b).

## 6. Kiểm tra lặp lại trên vault thử

Mười câu trên đã có script chạy lại được, chỉ trên ba vault thử (không bao giờ trên vault thật):

`node tests/e33-readonly-check.mjs --vault vault-copy`

Script chạy đúng các lệnh bridge chỉ-đọc, tính đáp án từ file, so sánh và in `PASS` hoặc `FAIL` cho từng câu, rồi kiểm tra vault không đổi (git HEAD, git status và dấu vân tay của mọi file). Chi tiết: `tests/scenarios/README.md`, mục "E3.3a".
